# Phase A/B Combined Diagnosis — full tracer reports



## [wave 1] blinnphong

### Mechanism

## How the viewer draws Blinn-Phong (LLMaterial) faces, end to end

**Pool and program selection.** Deferred is unconditional: `RenderDeferred` is deprecated and hardcoded true (pipeline.cpp:1230), and `deferred_class = 3` is hardcoded (llviewershadermgr.cpp:620), so the class3 `deferred/materialF.glsl` is always the fragment source (class1 materialF.glsl is a debug stub that outputs constant purple). LLDrawPoolMaterials has 24 deferred passes (12 x rigged/non-rigged, lldrawpoolmaterials.cpp:47-51). `beginDeferredPass` maps pass -> `gDeferredMaterialProgram[idx]` via `shader_idx[]` (lldrawpoolmaterials.cpp:63-85): idx bit0-1 = diffuse alpha mode (0 NONE, 1 BLEND, 2 MASK, 3 EMISSIVE), bit2 = HAS_SPECULAR_MAP, bit3 = HAS_NORMAL_MAP, bit4 (0x10) = skinned (llviewershadermgr.cpp:1319-1370). The BLEND variants (idx 1,5,9,13) are never drawn by this pool (commented out, lldrawpoolmaterials.cpp:66-78); alpha-blended Blinn-Phong faces are drawn by LLDrawPoolAlpha which binds `gDeferredMaterialProgram[mask]` directly (lldrawpoolalpha.cpp:895). Variant selection among the 12 is driven purely by per-face LLMaterial content (normal/spec map presence + alpha mode via `type_list[]`, lldrawpoolmaterials.cpp:108-141), NOT by settings.

**Settings that change the programs.** `RenderShadowDetail > 0` (with deferred level > 1) sets `use_sun_shadow` (llviewershadermgr.cpp:1097-1098) which adds the HAS_SUN_SHADOW permutation to every material program (llviewershadermgr.cpp:1349-1352) — so toggling shadows recompiles all 32 material programs with different source. More importantly, RenderShadowDetail, RenderDeferredSSAO, RenderGlow, RenderGlowNoise, RenderGammaFull, RenderMaxTextureIndex, RenderAvatarCloth, terrain-PBR settings, TerrainPaintBitDepth, RenderTransparentWater, and the HDR/emissive toggles are all wired to `handleSetShaderChanged` -> `LLViewerShaderMgr::setShaders()` (llviewercontrol.cpp:1325-1516, 261-277, 314-367) — a FULL unload+recompile of every program. `RenderVSyncEnable` is wired to `handleVSyncChanged` only (llviewercontrol.cpp:1363) and does NOT reload shaders, so vsync alone cannot trigger the symptom.

**Texture channels.** Material programs are NOT indexed: no `mIndexedTextureChannels` is set for gDeferredMaterialProgram (llviewershadermgr.cpp:1294-1376; contrast the indexed list at 1237, 1944 etc.), so they declare a single `uniform sampler2D diffuseMap` plus `bumpMap`/`specularMap` under #ifdef (class3/deferred/materialF.glsl:193-200). Channels are assigned dynamically at link: `mapUniforms()` walks active uniforms and `mapUniformTextureChannel` hands out `mActiveTextureChannels++` in mapping order (llglslshader.cpp:865-895), with a reorder hack that maps diffuseMap first, then specularMap, then bumpMap, then environmentMap, then reflectionMap when any of those enumerate before diffuseMap (llglslshader.cpp:944-1035). Indexed programs (simple/fullbright etc., `mIndexedTextureChannels = sIndexedTextureChannels = 4`, llviewershadermgr.cpp:576) get a post-link override that pins `tex0..tex3` to channels 0..3 and shifts every other mapped channel up by 4 (llglslshader.cpp:503-537) — which is why the bridge's units 0..3 scrape works for batched draws: `pushBatch` binds `mTextureList[i]` literally to units 0..N-1 (lldrawpool.cpp:591-596).

**Per-draw binding in the materials pool.** `renderDeferred` resolves channels once per pass via `enableTexture(DIFFUSE_MAP/SPECULAR_MAP/BUMP_MAP)` (lldrawpoolmaterials.cpp:156-158; enableTexture returns `mTexture[uniform]`, llglslshader.cpp:1270-1289), then per LLDrawInfo binds `params.mNormalMap` / `params.mSpecularMap` / `params.mTexture` to those units with `bindFast` (lldrawpoolmaterials.cpp:222-247) and sets four per-batch uniforms with RAW `glUniform*` calls (NOT the LLGLSLShader wrappers, so nothing lands in the `mValue` cache the bridge reads): SPECULAR_COLOR = params.mSpecColor, ENVIRONMENT_INTENSITY = params.mEnvIntensity, MINIMUM_ALPHA = params.mAlphaMaskCutoff, EMISSIVE_BRIGHTNESS = mFullbright (lldrawpoolmaterials.cpp:151-220). Texture animation rides `params.mTextureMatrix` loaded into gGL's texture matrix before the draw (lldrawpoolmaterials.cpp:263-272), which the tap correctly captures via `gGL.getTextureMatrix0()` (fsscenedump.cpp:385). Then `drawRange` fires the tap (llvertexbuffer.cpp:959/972/986).

**position.w indexing does NOT apply to materials.** materialV.glsl consumes `in vec3 position` — .w unused (class1/deferred/materialV.glsl:45,87). Faces with a non-empty materials block are excluded from texture batching (`can_batch_texture`, llvovolume.cpp:5452-5477) and get textureIndex 0 or FACE_DO_NOT_BATCH_TEXTURES=255 (llvovolume.cpp:6690-6790, llface.h:62); `getGeometryVolume` writes position.w's integer bit pattern as `mTextureIndex < 255 ? mTextureIndex : 0` (llface.cpp:2109-2121), so Blinn-Phong vertices always carry w-bits = 0 and the engine's `clamp(floatBitsToInt(pos.w),0,3)` (live.vert:37) selects slot 0. Diffuse-only rendering of materials faces is therefore correct **iff the bridge's tex[0] is the diffuse map** — i.e. iff `mTexture[DIFFUSE_MAP]` is valid and the pool actually bound the diffuse there.

**Why it breaks after a settings change (the full chain).** `setShaders()` calls `unloadShaders()` (llviewershadermgr.cpp:588); every program's `unloadInternal` calls glDetachShader/glDeleteShader/glDeleteProgram (llglslshader.cpp:373-384). Under the null-GL stub, glDeleteProgram/glDeleteShader/glDetachShader are NOT in the special table (opengl32.c:1100-1142) so `wglGetProcAddress` hands back the benign `ng_zero` stub (opengl32.c:1144-1152): **nothing is ever freed**. The stub's bookkeeping is fixed-capacity, append-only, keyed by monotonically increasing ids (`next_id`, opengl32.c:209-210): `g_progs` NG_MAX_PROGS=512 (opengl32.c:805), `g_proguni` NG_MAX_PROGUNIS=256 (opengl32.c:929), `g_shaders` NG_MAX_SHADERS=2048 (opengl32.c:804). One full load creates roughly 250+ programs (132 createShader call sites plus the 32-program materials loop, GLTF variants and rigged variants), each of which consumes a g_progs slot at glAttachShader time (opengl32.c:854-860) and a g_proguni slot when mapUniforms queries GL_ACTIVE_UNIFORMS (opengl32.c:712, 983-1009). So the FIRST load lands just under the 256-entry proguni cap — everything works — and the reload triggered by ANY settings change blows past both caps. For every program created after exhaustion: `proguni_get` returns NULL -> GL_ACTIVE_UNIFORMS = 0 (opengl32.c:986, 1002-1009) -> `mapUniforms` maps NOTHING (llglslshader.cpp:1039-1046 loops over 0) -> `mUniform`/`mTexture` stay all -1; and `prog_find(create=1)` returns NULL so attached shaders are dropped -> `ng_attrib_loc` returns -1 for every attribute (opengl32.c:898-920) -> `mAttributeMask` = 0.

Downstream in the materials pool: `enableTexture` returns -1 for all three channels; every `bindFast` goes to `gGL.getTexUnit(-1)` which is the dummy unit (llrender.cpp:1511-1522), so the diffuse/normal/spec of the CURRENT frame are bound NOWHERE. The bridge then computes `tex_base` from `mTexture[DIFFUSE_MAP]` = -1, falls back to 0 (fsscenedump.cpp:276-287), and scrapes units 0..3 (fsscenedump.cpp:288-292) — which still hold whatever the last *working* binds left there: unit 0 keeps being overwritten by non-materials pools that bind unit 0 unconditionally (lldrawpool.cpp:603), while units 1-2 are frozen at the last specular/bump maps the pre-reload materials pass bound (under the stub the reorder hack fires for material programs — the stub's `ng_loc` returns a location for ANY queried name including "reflectionMap"/"altDiffuseMap" the program doesn't declare (opengl32.c:745-764), and mapUniforms never resets `reflectionMap` after re-scanning (llglslshader.cpp:949 vs 960), so `refLessDiff` is true and diffuse/spec/bump land on channels 0/1/2, llglslshader.cpp:1005-1034). Result: every Blinn-Phong draw ships a bind_key of stale, unrelated texture ids — different stale ids as the frame's pool order churns unit 0 (the camo patchwork), including latched specular maps (gold/black) and normal maps sampled as diffuse color. Indexed (simple/fullbright) batches survive longer because pushBatch binds units 0..3 without consulting the shader — until g_progs exhaustion also zeroes their attributes and typemask-0 immediate draws start disappearing (the engine rejects typemask&1==0, live.rs:501). A second interplay: `mapUniform(reflectionMap)` is then called with a NAME-TABLE index misused as an active-uniform ENUM index (llglslshader.cpp:1030-1033), mapping an arbitrary uniform early — deterministic but wrong, another stub-honesty hazard.

### Bridge gaps

Ordered gaps vs the current bridge (fsscenedump.cpp / opengl32.c / live.rs):

1. **Stub tables are append-only and fixed-capacity; deletes are no-ops.** glDeleteProgram/glDeleteShader/glDetachShader resolve to `ng_zero` (absent from NG_SPECIAL, opengl32.c:1100-1152), while `setShaders()` recreates ~250+ programs per reload (llviewershadermgr.cpp:588, llglslshader.cpp:373-384). g_proguni caps at 256 (opengl32.c:929), g_progs at 512 (opengl32.c:805), g_shaders at 2048 (opengl32.c:804). One settings change exhausts proguni/progs -> every later-created program reports 0 active uniforms (opengl32.c:1002-1009) and -1 attributes (opengl32.c:898-920) -> mTexture[DIFFUSE_MAP]=-1, textures bound to the dummy unit, bridge scrapes stale units. THIS is the settings-change symptom's root cause.

2. **The tap has no per-draw material identity — it scrapes gGL texture units.** For materials draws, tex[0] is only the diffuse by the accident that channel assignment put diffuseMap at the unit the pool bound (fsscenedump.cpp:276-292). LLDrawInfo already carries the truth (mTexture, mNormalMap, mSpecularMap, llspatialpartition.h:135 area; bound at lldrawpoolmaterials.cpp:222-247) but nothing ships it.

3. **No alpha-mode/cutoff data.** MINIMUM_ALPHA is set with a raw `glUniform1f` (lldrawpoolmaterials.cpp:209-213) bypassing the mValue cache the bridge reads for DIFFUSE_COLOR (fsscenedump.cpp:305-322), and the stub only forwards the "color" uniform (opengl32.c:780-787). The engine's rule "blend-off => alpha 1" (live.frag:27-31) makes DIFFUSE_ALPHA_MODE_MASK faces (deferred, blend OFF) fully opaque — cutout textures lose their holes. EMISSIVE passes (diffuse alpha = emissive strength, class3 materialF.glsl:274-279) coincidentally survive because blend-off forces alpha 1, but only by accident.

4. **No specular/env/glossiness or normal/spec UV streams.** SPECULAR_COLOR, ENVIRONMENT_INTENSITY, EMISSIVE_BRIGHTNESS are raw glUniform calls the bridge never sees (lldrawpoolmaterials.cpp:151-220); the engine binds only TYPE_VERTEX/TEXCOORD0/COLOR (live.rs:672-687, 804-814) though TEXCOORD1/2 offsets are already shipped in d.offsets (materialV.glsl:91-98 shows norm/spec UVs are separate attributes through the same texture_matrix0).

5. **Engine geo cache keyed by CPU pointer with no destructor invalidation.** `fsr_buffer_dirty` fires only from flush_vbo writes (llvertexbuffer.cpp:1491-1495); a destroyed LLVertexBuffer whose shadow address is recycled at the same byte length reuses the stale GPU copy (live.rs:469-474). Narrow window, but a real staleness class the settings change (releaseGLBuffers/createGLBuffers, llviewershadermgr.cpp:586,736) exercises.

6. **Stub `ng_loc` invents locations for undeclared uniform names** (opengl32.c:745-764), which combined with mapUniforms not resetting `reflectionMap` (llglslshader.cpp:949,960,1008) makes the reorder hack fire for essentially every textured program and calls mapUniform with a name-table index as an enum index (llglslshader.cpp:1030-1033). Currently benign-to-helpful (diffuse lands on channel 0) but it is unearned behavior the bridge implicitly depends on.

### Fix plan

Ordered, independently testable fixes:

1. **STUB (root cause): implement object deletion + unbounded tables.** Add `glDeleteProgram`, `glDeleteShader`, `glDetachShader` to NG_SPECIAL (opengl32.c:1100-1142): glDeleteShader frees `g_shaders[i].src` and vacates the slot; glDeleteProgram vacates the g_progs entry AND its g_proguni entry; make the three linear arrays reuse vacated slots (or replace with growable storage under g_lock). Data to flow: none new — this preserves the existing per-program uniform/attrib resolution across arbitrarily many `setShaders()` reloads. Unblocks: correct mTexture[DIFFUSE_MAP]/attrib mapping after ANY settings change, for ALL pools (materials, bump, alpha, immediate UI). Test: toggle RenderShadowDetail 0<->2 five times in-world; Blinn-Phong meshes must keep their diffuse; %TEMP%\nullgl.log must show no new failures; add a one-line stat (progs live/freed) to verify reuse.

2. **TAP: ship authoritative per-draw material data instead of unit scraping.** Add a staged materials block to FSSceneDump (same pattern as terrain aux / KHR staging, fsscenedump.cpp:130-168): in LLDrawPoolMaterials::renderDeferred (before drawRange, lldrawpoolmaterials.cpp:279) and in LLDrawPoolAlpha's materials branch (lldrawpoolalpha.cpp:895), call e.g. `FSSceneDump::setMaterialBatch(diffuse_glname, norm_glname, spec_glname, alpha_mode, params.mAlphaMaskCutoff, params.mSpecColor, params.mEnvIntensity, params.mFullbright)` taken straight from LLDrawInfo, and clear it in endDeferredPass. Extend FsrDrawDesc (fsscenedump.cpp:50-65 / live.rs:27-49) with these fields (or a new draw_class = MATERIALS reusing tex_ex/aux). Engine: when the materials block is present, build bind_key from the staged diffuse id (slot 0), ignoring the scraped units. Unblocks: correct diffuse for every Blinn-Phong face independent of channel assignment, even if fix 1 regresses. Test: a normspec-mask test object renders its diffuse before AND after settings changes.

3. **ENGINE: alpha-mode-correct diffuse.** Put alpha_mode + cutoff into the ring-UBO block (live.rs:575-583, live.frag U block): MASK => `discard` when `t.a * v_color.a < cutoff` even when blending is off (replacing the blanket `c.a = 1.0`, live.frag:27-31); EMISSIVE => keep alpha forced to 1 (never treat diffuse alpha as coverage); NONE => current blend-off behavior. Unblocks: cutout foliage/gratings with Blinn-Phong masks. Test: alpha-masked material face shows holes; emissive-mode face stays opaque.

4. **ENGINE (later, lit): consume the rest of the trio.** Bind TYPE_TEXCOORD1/TEXCOORD2 streams (offsets already in d.offsets; live.rs vertex layouts at 672-687 gain two slots), route staged norm/spec ids into engine slots 1/2 deliberately, and use spec_color.rgb, glossiness = spec_color.a, env_intensity from the staged block for Blinn-Phong shading per class3 materialF.glsl:247-309 semantics. Test: gloss highlight parity screenshot vs stock GL.

5. **Hygiene: close the geo pointer-reuse hole.** Call `FSSceneDump::bufferDirty(mMappedData)` (and for index shadow) in LLVertexBuffer's destructor so live.rs `geo` (live.rs:469-490) never serves a stale GPU copy to a recycled allocation. Test: settings change + region teleport shows no misshapen/mis-UV'd meshes.

6. **Optional stub honesty: per-program uniform locations.** Make `ng_loc` consult proguni for the program and return -1 for undeclared names (opengl32.c:745-764), removing the accidental reorder-hack dependence (llglslshader.cpp:949-1034). Do this only after fix 2 lands (the bridge then no longer cares which channel diffuse gets). Test: channels still stable across reloads; no camo regressions.


## [wave 1] pbr

### Mechanism

== How the viewer renders GLTF/PBR faces, end to end ==

FACE CLASSIFICATION (rebuild time): llvovolume.cpp:6938-6952 — a face with a GLTF render material goes to exactly one of three passes by mAlphaMode: ALPHA_MODE_BLEND -> PASS_ALPHA (alpha pool), ALPHA_MODE_MASK -> PASS_GLTF_PBR_ALPHA_MASK, else PASS_GLTF_PBR (both opaque pool POOL_GLTF_PBR, llvovolume.cpp:6202-6205). PBR faces are batched WITHOUT indexed texturing: can_batch_texture() returns false for GLTF materials (llvovolume.cpp:5490-5492) and genDrawInfo is called for sPbrFaces with batch_textures=false (llvovolume.cpp:6441), so one LLDrawInfo == one material (params.mGLTFMaterial set at llvovolume.cpp:5804).

VERTEX STREAM: pbr_mask = TEXCOORD0|NORMAL|VERTEX|COLOR|TANGENT (llvovolume.cpp:6399), + MAP_EMISSIVE if any face in the group has glow (llvovolume.cpp:6401-6410), + MAP_TEXTURE_INDEX via extra_mask (llvovolume.cpp:6429). The COLOR attribute IS the GLTF baseColorFactor: llface.cpp:1464-1467 (`color = tep->getGLTFRenderMaterial()->mBaseColor`) — "base color factor is baked into vertex stream" (llfetchedgltfmaterial.cpp:132). There is NO baseColorFactor uniform; the shader multiplies `basecolor *= vertex_color` (pbropaqueF.glsl:75). position.w still carries a texture-index bit pattern (llface.cpp:2109-2121) but STOCK PBR SHADERS NEVER READ IT — pbropaqueV.glsl:47 declares `in vec3 position`.

OPAQUE+MASK DRAW: LLDrawPoolGLTFPBR::renderDeferred binds gDeferredPBROpaqueProgram (plain, then bind(true) = rigged HAS_SKIN variant) and calls pushGLTFBatches (lldrawpoolpbropaque.cpp:53-69). pushGLTFBatch (lldrawpool.cpp:823-843): mat->bind(params.mTexture) -> per-draw cull disable if mDoubleSided (lldrawpool.cpp:832) -> setup_texture_matrix -> applyModelMatrix -> drawRange.

MATERIAL BIND (the single choke point, llfetchedgltfmaterial.cpp:65-150): (a) minimum_alpha uniform = mAlphaCutoff for MASK, else -1.0 (lines 69-84; also set during shadow render for MASK). (b) baseColorTex -> DIFFUSE_MAP channel, white fallback (86-93); media texture overrides base color AND emissive (74-75). (c) texture_base_color_transform (2x vec4 packed KHR) uploaded (95-97) and staged for the tap (101). (d) non-shadow only: normal -> BUMP_MAP (flat-normal fallback, and only if discard level <= 4), ORM -> SPECULAR_MAP (white fallback), emissive -> EMISSIVE_MAP (white fallback) (105-130); roughnessFactor, metallicFactor, emissiveColor uniforms (134-136); texture_normal_transform, texture_metallic_roughness_transform, texture_emissive_transform (138-148). There is NO emissiveStrength anywhere — grep finds no emissive_strength/EMISSIVE_STRENGTH in indra; the only emissive factor is the vec3 "emissiveColor" (llshadermgr.cpp:1288).

CHANNELS: not fixed constants. Channels are assigned sequentially at link time in uniform-enumeration order (llglslshader.cpp:865-895), with a forced reorder that maps diffuseMap first (then specularMap, bumpMap, environmentMap, reflectionMap) when the compiler enumerated any of those before diffuseMap (llglslshader.cpp:944-1034). emissiveMap is NOT in the reorder list, so its channel is enumeration-order dependent. Every relink recomputes channels and CLEARS the mValue uniform cache (llglslshader.cpp:904-911).

FRAGMENT (pbropaqueF.glsl): basecolor = srgb_to_linear(tex(diffuseMap, base_color_texcoord)); basecolor *= vertex_color; if (basecolor.a < minimum_alpha) discard (72-80). ORM: spec.g*=roughnessFactor, spec.b*=metallicFactor (98-101). emissive = emissiveColor * srgb_to_linear(tex(emissiveMap)) (103-104). GBuffer writes: diffuse, ORM, normal+PBR flag, and frag_data[3]=emissive ONLY under `#if defined(HAS_EMISSIVE)` (115-121). HAS_EMISSIVE comes from add_common_permutations gated on setting RenderEnableEmissiveBuffer, default FALSE (llviewershadermgr.cpp:270-278): OFF = opaque-PBR emissive is NOT written to the gbuffer at all (only the glow-bloom pass sees it); ON = emissive composited by softenLight.

UV TRANSFORM ORDER (textureUtilV.glsl:62-79): texcoord -> SL animation matrix (texture_matrix0) FIRST, then y-flip, KHR (offset*rotation*scale), y-flip back. Each of the four slots gets its OWN texcoord: base_color/normal/metallic_roughness/emissive_texcoord computed from the same TEXCOORD0 with per-slot KHR uniforms (pbropaqueV.glsl:85-88). Uniform names: texture_base_color_transform, texture_normal_transform, texture_metallic_roughness_transform, texture_occlusion_transform (reserved but never set — occlusion is folded into ORM), texture_emissive_transform (llshadermgr.cpp:1239-1243).

BLEND MODE: alpha pool, LLDrawPoolAlpha::renderAlpha — gltf BLEND draws switch to pbr_shader = gDeferredPBRAlphaProgram (gHUDPBRAlphaProgram for HUDs; rigged variant per draw) and call params.mGLTFMaterial->bind (lldrawpoolalpha.cpp:843-862); blend func comes per draw from params.mBlendFuncSrc/Dst (lldrawpoolalpha.cpp:957). The real class2 pbralphaF.glsl multiplies vertex_color.rgb * linearized base color and lights it; minimum_alpha exists only under HAS_ALPHA_MASK which gDeferredPBRAlphaProgram does NOT define (llviewershadermgr.cpp:1493-1507: DIFFUSE_ALPHA_MODE=BLEND, HAS_NORMAL_MAP/HAS_SPECULAR_MAP/HAS_EMISSIVE_MAP/USE_VERTEX_COLOR, optional HAS_SUN_SHADOW). NOTE: class1/deferred/pbralphaF.glsl in this tree is a magenta debug stub (checked into git at e0cd8e2b90); class2 is the real shader.

GLOW: renderPostDeferred with color mask (false,true) — gPBRGlowProgram writes rgb=0, a=luminance(emissive)*vertex_emissive.a into the glow/alpha channel only (lldrawpoolpbropaque.cpp:83-93, pbrglowF.glsl:57-65). Alpha-pool PBR emissives similarly draw with blendFunc(ZERO, ONE, ONE, ONE) so color is a no-op (lldrawpoolalpha.cpp:997-999, 600-612).

HUD: sRenderingHUDs swaps to gHUDPBROpaqueProgram (IS_HUD permutation — forward fullbright: col = vertex_color.rgb*srgb_to_linear(base) + emissive, pbropaqueF.glsl:146-167).

SETTINGS THAT SWAP/RELINK PROGRAMS: RenderEnableEmissiveBuffer (handleEnableEmissiveChanged -> release GL buffers + setShaders, llviewercontrol.cpp:352-366 and 1346) toggles HAS_EMISSIVE on ALL common-permutation programs including all four PBR programs; RenderShadowDetail (llviewercontrol.cpp:1380) flips use_sun_shadow (llviewershadermgr.cpp:929-930) = HAS_SUN_SHADOW permutation on gDeferredPBRAlphaProgram; RenderDeferredSSAO, RenderGlow, RenderGlowNoise, RenderGammaFull, RenderAvatarCloth, RenderMaxTextureIndex, RenderTerrainPBRDetail/PlanarSampleCount/TriplanarBlendFactor, TerrainPaintBitDepth all run handleSetShaderChanged (llviewercontrol.cpp:1325-1516) which rebuilds EVERY program — new channel assignments, cleared mValue caches.

### Bridge gaps

Ordered gaps, each verified against the bridge sources (fsscenedump.cpp, live.rs, live.vert, live.frag):

1. [CONFIRMED — likely the "PBR meshes swap textures" symptom] position.w indexed-texture selection is applied to PBR draws that must never use it. live.vert:35-37 does floatBitsToInt(pos.w) for EVERY generic draw and live.frag:17-22 selects among tex[0..3]; but stock PBR shaders declare `in vec3 position` and ignore w (pbropaqueV.glsl:47), and the tap's tex[1..3] for PBR programs are NOT a diffuse array — they are whatever sits on raw units diffuseMap_channel+1..+3 (fsscenedump.cpp:288-292): some permutation of bumpMap/specularMap/emissiveMap (channel order enumeration-dependent, llglslshader.cpp:944-1034, emissiveMap not even in the reorder list) plus unrelated samplers (lightMap etc. for the alpha program). The value is recoverable per draw exactly like DIFFUSE_COLOR: sh->mUniform[LLShaderMgr::MINIMUM_ALPHA] + sh->mValue (uniform1f caches at llglslshader.cpp:1377-1384; reserved name "minimum_alpha" llshadermgr.cpp:1357).

### Fix plan

RECOMMENDATION: GPU skinning in the engine's vertex shader, palette in a second dynamic-offset uniform binding. CPU pre-skinning is disqualified structurally: it would rewrite vertex bytes every frame, invalidating the pointer-keyed geometry cache (live.rs:103-106 — upload-once was the fix for the CPU hog) and re-uploading MBs/frame; whereas joints+weights are ALREADY in the shipped VB bytes (TYPE_WEIGHT4, offsets already computed at live.rs:655-664) and a palette is only ≤110×48 = 5280 bytes per (avatar, mesh) per frame. wgpu default limits are ample (64 KiB max UBO binding).
